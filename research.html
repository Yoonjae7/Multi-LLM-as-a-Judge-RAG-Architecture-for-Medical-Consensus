Building a Multi-LLM-as-a-Judge System for Western Medicine Question Answering

Yoonjae Lee

School of Computer Science, University of Nottingham Malaysia

BSc (Hons) Computer Science with Artificial Intelligence

Supervisor: Dr Simon Lau Boung Yew

MediRAG-West Research report Not a medical device

Summary

AI chatbots often answer health questions confidently even when they are not sure they are right, and they do not show where the answer came from. We built MediRAG-West to fix that. Instead of one AI answering, three separate AI agents answer the same question from the same evidence, then a panel of four AI judges scores those answers before anything is shown to the user. If the system cannot find good evidence, or the question is an emergency, it stops and says so instead of guessing.

We used two free AI providers: Groq for the three agents, and Google Gemini for the four judges. This report explains why we split it that way, what we actually told each AI to do, what went wrong while building it, and what the system still cannot do.

1Why we built this

A single AI chatbot answering a health question has three problems. It states things confidently with no source, so you cannot check it. It gives one merged opinion where a real doctor would weigh a few possibilities. And it will happily answer things it should not, like an emergency, instead of telling you to get help immediately.

Other researchers have already shown partial fixes for each of these. Giving a model real documents to read before it answers reduces made-up facts[1]. Having a few AI agents answer independently and then compare notes improves accuracy over one agent alone[2]. Using an AI to grade another AI's answer works reasonably well, roughly as well as two humans agree with each other[3]. And medical hallucination is a known, measured problem that does not go away just because a model is bigger[4].

Nobody had put all four of these together into one small, working, free system. That is what this project does.

Scope

This report only covers the Western medicine part of the project, called MediRAG-West. A separate Traditional Chinese Medicine module exists in the same repository but is not part of this report. MediRAG-West gives health information, not a diagnosis or a treatment plan, which keeps it outside the rules that apply to regulated medical software[6].

2The AI models we used

We used two different AI providers on purpose, not the same one for everything.

Both Groq and Gemini offer a free tier that needs no credit card, which is what makes this project realistically deployable by a student rather than something that only works with a company's budget.

The reason for splitting agents and judges across two different companies is not just cost. AI models are known to be a little biased in favour of answers that look like their own writing style[3]. If a judge and an agent were the same model, the judge might rate that agent's writing style more kindly without meaning to. Using Groq for agents and Gemini for judges means a judge is never grading its own kind.

The emergency check does not use AI at all. It is a plain list of warning phrases checked in the browser before anything is sent anywhere. We chose this on purpose: an emergency check needs to be predictable and instant, not something that depends on how a language model happens to interpret a sentence that day.

3How the system works

The system has six steps. Two of them can stop everything early, on purpose.

1. Question. The user types a health question into a text box.

2. Query Planner. Before anything else, plain code checks the question against a list of emergency warning phrases (chest pain, stroke signs, severe bleeding, thoughts of self-harm). If one matches, the system stops immediately and tells the user to get real help. No AI is called at this step at all.

3. MediRAG-West. If it is not an emergency, plain code searches a small library of about twenty real medical sources (NICE guidelines, WHO guidance, and similar) by matching keywords in the question against keywords in each source. This is a simple search, not a fancy AI search, and that is fine because it only has one job: find sources that are actually relevant, or admit that none are. Each source is also labelled with how strong its evidence is, high, moderate, or low certainty, based on the GRADE system doctors already use for this[5]. If nothing scores high enough, the system stops here and tells the user it found no good evidence, instead of letting an AI guess from memory.

4. Agent Debate. If evidence was found, three AI agents (Western Medicine, Nutrition, Lifestyle) each answer the same question from the same evidence, at the same time, without seeing each other's answers first. Then a fourth AI call shows all three answers to each other and asks: did anyone say something the evidence does not support, and do any two of them actually disagree?

5. SafeJudge. Four more AI calls, one per judge, score the (now revised) answers on evidence quality, safety, conflict, and whether the stated confidence matches the evidence. Each judge only sees the answers with the agent's name hidden and the order shuffled, so it cannot just favour whichever agent it saw first. If the Safety Judge finds a real problem, it can block the whole answer. This is not a vote, a bad safety score overrides everything else, it is not averaged away by the other three judges.

6. Final answer. One last AI call combines everything into a plain-language answer, alongside a confidence score we calculate ourselves from the real evidence scores and real judge scores, not asked from the AI.

4The prompts we wrote

Every AI call in this system is given a system prompt, instructions that tell it what job it has and what it is not allowed to do. Here is what we actually wrote, word for word, for each one.

The three specialist agents

Each agent gets the same base rules, plus one line that narrows its job:

Western Medicine Agent

"You cover what the condition may be, red-flag symptoms, when to seek professional care, and medication cautions."

Nutrition Agent

"You cover dietary factors that have real mechanistic or trial support for this question."

Lifestyle Agent

"You cover sleep, activity, behaviour and stress factors relevant to this question."

All three also get this shared rule, so none of them accidentally acts like a doctor:

Shared rule, appended to every agent

"Use only the supplied evidence. Do not use outside medical knowledge or invent sources. Do not diagnose, prescribe, name a dose, or tell the user to start, stop or change a medication. If the evidence is thin, say so plainly instead of sounding more certain than you are. Write two to four plain sentences a layperson can follow. No headings, no bullet points, no markdown."

We also force every answer into a strict format, so our code never has to guess what the AI meant: {"text": "...", "confidence": 0.0, "strength": "Low|Moderate|High", "cited_evidence_ids": ["E1"], "gap": "..."}. The "gap" field asks the AI to say what it could not figure out, which turned out to be one of the more useful fields, it stops the agent from pretending it covered something it did not.

The debate step

Debate prompt

"Three specialist agents have each answered the same question from the same evidence. Read their answers and decide, for each agent, whether anything they said overstates the evidence, and whether any two agents materially disagree (not just differ in emphasis). ... Do not invent disagreements that are not really there."

That last sentence exists because early on we noticed the model wanted to find a disagreement even when there was not a real one, presumably because "agents in conflict" sounds like a more interesting answer than "they agree."

The four judges

Each judge gets a one-line job description:

Evidence Judge

"Check whether every claim traces back to the supplied evidence and whether the cited evidence ids actually support what is claimed."

Safety Judge

"Check for contraindications, missed red flags, drug interaction risks, or advice that could delay proper care. ... If you find a real safety problem serious enough that this answer should not reach the user as written, set veto to true."

Conflict Judge

"Check whether the agents materially disagree with each other, as opposed to just covering different ground."

Confidence Judge

"Check whether the certainty in each answer is proportionate to the strength of the evidence behind it."

All four also get this line, to stop one good score from leaking into another:

Shared rule, appended to every judge

"Score independently. Do not let a good score on one aspect inflate your score on this one."

The final answer

Consensus prompt

"Merge them into one coherent answer in plain language, four to six sentences, that a layperson can follow. Mention any real disagreement between agents rather than hiding it. Do not diagnose, prescribe, or name a dose."

5Problems we ran into

Building this surfaced real problems, not just design decisions on paper.

AI answers are not always valid JSON

We ask every AI call to return JSON so our code can read it directly. In practice, models sometimes wrap the JSON in a code block, or add a sentence before it. Our code now looks for the first { and last } in the response and tries to parse just that part, rather than assuming the whole response is clean JSON. Without this, a perfectly good answer could fail to display just because of one stray sentence around it.

Our first search had a false-match bug

Our keyword search originally checked whether a word from the question appeared anywhere inside a source's text. This backfired: the word "how" (from "how do I bake bread") matched because it is hiding inside the word "show" in an unrelated sentence, and the system returned medical evidence for a question about baking. We fixed it by matching whole words only, not substrings. This is the kind of bug you only catch by actually testing with odd questions, not by reading the code.

Free AI providers have rate limits

Groq and Gemini's free tiers cap how many requests you can make per minute and per day. One question uses about nine AI calls, so a shared free key supports roughly a hundred full questions a day before someone gets a "please slow down" error. We made sure that error shows up clearly to the user instead of the page silently breaking.

We could not fully test with real API keys during development

We built and tested the whole pipeline by faking what Groq and Gemini would send back, checking that our code handles success, errors, and badly formatted responses correctly, before ever calling the real APIs. This caught the JSON and search bugs above before they reached a real user.

A judge should not grade its own kind

This was less a bug and more a design worry: if the same AI company answered and judged, would the judge unfairly favour writing that reads like its own style? We do not have proof either way, since we have not run the direct comparison, but splitting agents and judges across two different providers removes the question entirely rather than trying to correct for it afterward.

6Limitations

Stated plainly

This is a working prototype, not a tested medical product, and nothing here should be read as proof that the system gives correct medical answers.

  • No clinical testing. No doctor has reviewed the outputs at scale. It should never be used for a real health decision.
  • Small evidence library. About twenty sources is tiny compared to real medical literature, so many real questions will get a "not enough evidence" response.
  • Simple search. Keyword matching is easy to build and explain, but it will miss questions phrased very differently from our source text. A smarter, meaning-based search would catch more of these.
  • Judges are AI too. Using AI to check AI cannot fully remove bias, it can only reduce it. A human should still review this before anyone trusts it.
  • The confidence number is our own formula, not something proven against real outcomes. Treat it as a rough guide, not a statistic.
  • Free tier limits. This will not hold up under heavy public traffic without a paid plan.

7Conclusion

We built a small, working, free system where three AI agents answer a health question independently, a fourth AI call compares their answers, four more AI calls judge them on different criteria, and only then is one answer shown, with its evidence and confidence attached. Two design choices mattered most: splitting agents and judges across different AI providers so a judge never grades its own kind, and making the system stop and say "I don't know" when it has no good evidence, instead of guessing.

Building it surfaced real, ordinary engineering problems, messy JSON, a search bug, rate limits, more than any deep theoretical one. That is probably the most honest thing this report can say.
